# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`eqxva` is an exposure engine for counterparty risk. It produces EE/NEE/PFE, EPE/EEPE, FCA/FBA funding exposure and SA-CCR EAD profiles on user-defined buckets for equity TRS, European options and commodity bullet swaps. **Scope stops at exposure and SA-CCR EAD**: it does not compute CVA/DVA/FVA charges or a hurdle. Methodology, input sheet columns and known simplifications are documented in detail in `README.md`; read the relevant section before changing behaviour.

Gas prepay swaps: see `docs/prepay/context.md` and `docs/prepay/INTEGRATION.md` before working on prepay exposure or capital. In the engine they are COMSWAP strips with leg-level exposure windows (`active_from`/`active_to`, `window_months`), SA-CCR overrides (`sa_maturity`, `sa_fixed_notional`, `sa_notional_basis` AMORT) and an optional path-by-path PV import (`pathimport.py`, NettingSets `value_source` IMPORT). Inputs come from `commodity/prepay_examples.py`, tests are in `tests/test_prepay.py`, and the README has a "Gas prepay swaps" section. The scripts those docs call `scripts/*.py` and `outputs/` live in `reference/prepay/`. They are standalone prototypes for checking results, not code to copy into the engine. The XVA write-up (a Claude Doc) is refreshed from engine results with `examples/prepay/xva_writeup.py`; the steps and the table-to-section map are in `docs/prepay/XVA_WRITEUP.md`.

## Commands (Windows, project-local venv)

```
python -m venv .venv
.venv\Scripts\python -m pip install -e .[excel,dev]        # add [bloomberg] for xbbg
.venv\Scripts\python -m pytest                              # all tests
.venv\Scripts\python -m pytest tests\test_commodity.py -k calibration   # one file / one test
.venv\Scripts\python -m eqxva run examples\trades_example.xlsx [--out f.xlsx] [--paths N] [--seed N] [--no-analytic]
.venv\Scripts\python -m eqxva template my_inputs.xlsx       # write an example equity input workbook
.venv\Scripts\python excel\build_workbook.py                # rebuild EquityXVA_Exposure.xlsm
.venv\Scripts\python excel\build_commodity_workbook.py      # rebuild CommodityXVA_Exposure.xlsm
```

- `run` writes `<input>_results.xlsx` next to the input. It fails with `PermissionError` if that file is open in Excel.
- There is no linter or formatter configured, and the folder is not a git repo. Dated `backup_*` folders are manual snapshots: don't edit them or search them as if they were live code.

## Architecture

One engine (`src/eqxva`) with two front ends that both call it:
- **CLI**: `cli.py` → `io_excel.read_workbook` / `parse_inputs` → `exposure.run_monte_carlo` → `analytic.run_analytic` → `io_excel.write_results`.
- **Excel**: `excel/<Name>.xlsm` runs via the xlwings macro, which imports `excel/<Name>.py`, which calls `xl_entry.dispatch`. The Control sheet's `Action` cell selects `RUN_ALL` / `RUN_MC` / `RUN_ANALYTIC` / `BBG_REFRESH` / `CLEAR`. The `.py` and `.xlsm` base names must match. The workbooks are generated by `excel/build_*.py`, which embed this machine's interpreter path and PYTHONPATH, so change the builder and rebuild rather than hand-editing the `.xlsm`.

Pipeline inside the engine:
1. **Parsing** (`io_excel.parse_inputs`): reads the Config / Market / Curve / FX / VolSurface / Correlation / NettingSets / Trades sheets into `MarketData` (`market.py`), `NettingSet`/`Trade`/`CSA`/`RunConfig` (`model.py`) and a `warnings` list. Commodity sheets (Contracts, CommodityProducts, CommodityFactors, FactorCorrelation) are parsed by `commodity/io.py` into `mkt.commodity`; futures contracts are `FuturesContract`, a subclass of `Underlying`, so they sit in `mkt.underlyings` next to equities. `model.build_netting_sets` dispatches on `leg_type` (TRS / OPTION / COMSWAP) to `build_trs`, `build_option` or `commodity.swap.build_commodity_swap`.
2. **Grid** (`exposure.build_grid`): buckets plus every event date and the day before it, so pre-settlement peaks are captured. `fine_step` sets the internal step.
3. **Simulation** (`exposure.simulate_all`): equities use GBM in `simulation.py`; futures use the N-factor model in `commodity/nfactor.py`. The result is a dict `underlying -> (paths × grid)`. Equity and commodity draws are independent.
4. **Valuation** (`exposure.leg_value` / `value_cube`): per-leg closed form on each path, using `products/trs.py`, `products/option.py` and `commodity/swap.py`, converted to the CSA currency through deterministic FX forwards. **Adding a new product means touching `leg_value`, `leg_mtm0`, `saccr.leg_terms` / `sa_price` and the builder dispatch in `model.py`.**
5. **Collateral** (`collateral.py`): VM(t) = CSA(V(t − MPOR)) with thresholds, MTA, rounding and IA. Funding exposure uses unlagged collateral.
6. **SA-CCR** (`saccr.py`): CRE52 for equity and commodity, path-wise on the first 2,000 paths, margined/unmargined with the cap. Results are reported per bucket and at t=0 with leg and entity breakdowns.
7. **Bucketing / stats** (`exposure.bucketise`, `stats`, `Results`): `AVERAGE` (time average over (bucket_start, bucket_date]) or `POINT`; optional event buckets. `Results` turns everything into the output DataFrames/sheets.
8. **Analytic check** (`analytic.py`, `commodity/analytic.py`): Gauss–Legendre quadrature for exact uncollateralized EE/NEE on single-underlying equity sets; for commodity sets, exact integration (≤3 drivers) or a normal approximation, plus the `ExposureCompare` sheet.

Conventions that span files:
- Bank view: positive value = counterparty owes the bank.
- Cash flows on a grid date count as settled.
- Exposure and SA-CCR are 0 once the netting set has matured.
- `spot_shock` prices a trade on a shocked copy of its underlying (e.g. `SPCX+50%`). The copy shares random numbers and the SA-CCR entity with the original, so unshocked results are unchanged. It is not allowed on COMSWAP legs.
- Input problems that are not fatal go into `warnings` and end up on the Warnings sheet; real errors raise `ValueError` naming the trade.

## Tests

`tests/test_engine.py` (equity) and `tests/test_commodity.py` check against closed forms: Black-Scholes, quadrature EE, variance calibration and SA-CCR hand calculations. They build inputs from `examples.example_sheets()` / `commodity.examples.example_sheets()` with overrides and use small path counts. Keep that pattern for new tests. Prepay validation targets are listed in `docs/prepay/INTEGRATION.md`.
